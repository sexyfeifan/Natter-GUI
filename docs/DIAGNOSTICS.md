# 网络诊断与信息

v0.2.1 还显示原版 Socket 转发错误累计次数、最近错误时间与进程线程数。`Too many threads` 表示转发器已达到该服务配置的线程上限；原版默认为 128，面板可选 256、512、1024。该错误意味着新连接可能被拒绝；“进程运行中”及先前的 WAN 结果不能消除这一故障。保存线程上限会重启该服务，错误计数从新进程重新开始。UDP 使用原版上限且不受 TCP 选项影响。

v0.2.0 的“网络诊断”提供设备环境、服务连通和原版 NAT 检测。服务卡片的“诊断”按钮可检查单项服务；诊断页可选择全部服务并导出 JSON 报告。

## 网络体检

网络体检读取信息并连接已经配置的端口，不重启 Natter、不改路由、不创建 UPnP 租约，不做任意端口扫描。

| 信息 | 来源与用途 |
|---|---|
| 设备 / Python / UID | 当前面板执行环境，帮助确认账户和平台 |
| CPU、内存、运行时间 | Linux /proc 的短时采样和统计；不是压力测试或容器配额 |
| 网卡 IPv4、状态、MTU、协商速率、双工 | Linux iproute2 与 sysfs；不代表宽带上传速度 |
| 网卡当前收发、错误与丢弃 | 短时收发采样、累计错误/丢弃；包含设备其他应用流量 |
| 系统默认出口与 IPv4 策略路由 | 固定只读 iproute2 查询 |
| 面板 UID 实际出口 | 对 1.1.1.1 的路由查询，只查内核路由，不发送探测流量；绑定其他地址/网卡时还要核对对应配置 |
| 目标 TCP 端口 | GUI 从本机发起 TCP 连接，记录建连耗时 |
| Emby / Plex HTTP 响应 | 对已配置的常用8096/32400端口发送 HEAD；不带应用令牌、不跟随重定向 |
| 本地转发端口 | 检查实际绑定地址；不对已停止实例的历史端口进行测试 |
| 公网地址回环 | 从内网发起 TCP 连接，不能替代真正外网验证 |
| 原版 WAN | 原版运行日志快照，GUI 体检不重新构造或覆盖结论 |
| 公网映射与绑定地址 | 原版通知与日志；自动分配端口使用原版报告的实际地址 |
| UPnP 路由与错误 | 原版日志证据；发现路由不等于租约或外网可达已经独立验证 |
| TCP 对端、延迟、积压、重传、接收窗口受限 | Linux ss 快照，每个监听端口最多显示16条连接；可能包含保活连接 |
| 人工外网验证 | 已记录的外网结果；历史记录保持历史标记 |

HTTP 200、302、401、403 等都可以证明应用产生了 HTTP 响应，不能单凭响应码证明已登录、能播放或能下载。TCP 建连耗时不是应用响应时间或 ICMP ping。

目标或转发 TCP 端口明确拒绝连接时，GUI 探测标为 CLOSED。超时、网络不可达等记为 UNKNOWN，并保留原因。任务超过检测预算后跳过剩余探测，不把跳过的检查标成失败。

UDP 没有通用的“连接成功”判断：UDP socket 发送成功不证明数据已到达。体检不向 UDP 业务端口发送 TCP 探测，需要应用协议、回包或独立外网客户端验证。

体检任务异步执行，同一时间只允许一个任务。最多4个服务同时检测，每次 TCP 操作设置超时，服务探测共享30秒预算；加上环境查询与收尾通常在一分钟内结束。没有对应平台能力或命令时明确显示不可用，不填零假装已采样。

## NAT 类型解释

类型及原版状态来自未修改的 NatterCheck：

| 编号 | 中文含义 | 解释 |
|---|---|---|
| -1 | 无法判定 | 没有足够检测结果，原版显示 NA |
| 0 | 开放互联网 | 检测未发现地址转换，仍需要确认防火墙与服务 |
| 1 | 全锥形 NAT | 满足原版全锥形条件，适合 Natter 打洞 |
| 2 | 地址受限型 NAT | 通常只接受内网先联系过的外部 IP |
| 3 | 端口受限型 NAT | 通常只接受内网先联系过的外部 IP 和端口 |
| 4 | 对称型 NAT | 不同外部目的地的映射可能不同 |
| 5 | 对称型 UDP 防火墙 | 地址未转换，但 UDP 入站受限 |

这是原项目的编号，TCP 与 UDP 支持的分类范围不同。原版通常将0/1标为 OK、未知标为 NA、其他类型标为 FAIL；运行异常也可能输出 FAIL，需结合原始输出区分。GUI 原样保留状态并附加解释，不转换成“业务端口生效”。

类型检测使用独立临时端口，与某项业务服务的 UPnP 固定端口结果可能不同。“检测已结束”表示程序结束，需要查看各项结果。

## 快照与隐私

结果记录时间与耗时。服务配置、进程、启停状态或公网映射变化后，相关快照会标记为历史；网络本身可能在采样后变化，应按需要重新检测。诊断结果保存在当前面板进程内存中，面板重启后需要重新检测。

API：认证后 POST /api/diagnostics，空对象表示全部服务，或使用 {"service_id":"已配置的12位服务ID"} 检查单项。非 GET 请求仍需要登录 cookie 和 X-CSRF-Token。接口拒绝任意主机、命令或其他输入字段；结果通过已有 GET /api/state 的 diagnostics 字段查询。

导出报告包含网络地址、路由、TCP 对端和状态快照，不包含管理员认证配置或应用令牌。它可能含私有网络信息，分享前应自行检查。Docker 镜像包含 iproute2；原生设备缺少该工具时部分信息会明确显示不可用。

原生 systemd 单元允许 AF_NETLINK，以便非 root 面板账户读取网卡、路由和 TCP 统计；仍保留 NoNewPrivileges 和专用账户，没有授予 NET_ADMIN 或修改系统路由的权限。旧版本安装请重新执行新版安装脚本，使单元配置同步更新。

## 速度排查边界

协商1000Mbps只说明本地网口链路。采样流量包括 BT 等其他业务，不能代表可用上传带宽。发送队列、重传、延迟和接收窗口受限是线索，不单独证明运营商限速。

外网播放要比较家里上传、客户端下载、代理/VPN路径、直接播放/转码/间接连接和码率限制。BT 要比较入站连接、种子及相同任务。1 MB/s 约等于8 Mbps；本页没有带宽测速或限速解除功能。
